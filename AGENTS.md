# Publication instructions / Veröffentlichungsregeln

## English

- Publish public-facing documentation, changelog entries, new commit messages,
  release notes and pull-request titles/descriptions in both English and German.
  Put English first, followed by the corresponding German content; update both
  versions together. Use language links in longer documents.
- Keep code identifiers, commands and protocol values unchanged. Source-code
  implementation comments may remain in English.
- Publish only reviewed project source, synthetic tests, example configuration,
  licensing material and general documentation. Never publish real credentials,
  server or player data, local infrastructure paths, runtime logs, captures,
  server binaries, private research reports or private development history.
- Check the complete staged content and every outgoing commit before a push.
  Publishing a cleaned snapshot must not pull private ancestor commits into the
  public history. Existing private development checkouts remain separate.
- Preserve existing user changes and the original license. The German license
  document is a non-binding translation; it does not change the English original.
- Do not rewrite published history or change another person's fork without an
  explicit request. State validation results and remaining limitations accurately.

## Deutsch

- Öffentliche Dokumentation, Changelog-Einträge, neue Commit-Nachrichten,
  Versionshinweise sowie Pull-Request-Titel und -Beschreibungen auf Englisch und
  Deutsch veröffentlichen. Englisch zuerst, danach der entsprechende deutsche
  Inhalt; beide Fassungen gemeinsam aktualisieren. Längere Dokumente erhalten
  Sprachverweise.
- Codebezeichner, Befehle und Protokollwerte unverändert lassen. Interne
  Implementierungskommentare im Quellcode dürfen auf Englisch bleiben.
- Nur geprüften Projektquellcode, synthetische Tests, Beispielkonfiguration,
  Lizenzunterlagen und allgemeine Dokumentation veröffentlichen. Niemals echte
  Zugangsdaten, Server- oder Spielerdaten, lokale Infrastrukturpfade, Laufzeitlogs,
  Mitschnitte, Server-Binärdateien, private Forschungsberichte oder private
  Entwicklungshistorie veröffentlichen.
- Vor jedem Push den gesamten vorgemerkten Inhalt und jeden ausgehenden Commit
  prüfen. Die Veröffentlichung eines bereinigten Stands darf keine privaten
  Vorgänger-Commits in den öffentlichen Verlauf übernehmen. Bestehende private
  Entwicklungsordner bleiben getrennt.
- Vorhandene Nutzeränderungen und die Originallizenz erhalten. Das deutsche
  Lizenzdokument ist eine unverbindliche Übersetzung und ändert das englische
  Original nicht.
- Veröffentlichte Historie oder fremde Forks nur bei ausdrücklichem Auftrag
  ändern. Prüfergebnisse und verbleibende Einschränkungen korrekt benennen.
